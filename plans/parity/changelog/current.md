- **Glyph rendering: `PDFStreamEngine#showGlyph` dispatch + unified graphics state (2026-10-29, test-first)**: `PDFRenderer`/`PageDrawer` drew no text at all — `PDFStreamEngine#show_glyph` was a no-op, so `PageDrawer#show_font_glyph` was dead code (it even called non-existent `font.path`/`font.glyph_name`), and `PDFGraphicsStreamEngine` kept a second `@graphics_state_stack` of `PDGraphicsState` that the parent's text machinery never read, leaving `font` nil in the state the engine actually used. `PDFStreamEngine` now ports Java faithfully: a `create_graphics_state` factory (overridden by `PDFGraphicsStreamEngine` to push the Java-shaped `PDGraphicsState`) feeds the single `@graphics_stack` (typed `Array(GraphicsState | PDGraphicsState)` for the lighter engine), `save_graphics_stack`/`restore_graphics_stack` replace the ad-hoc `@graphics_stack.as(Array).map(&.clone)` snapshotting, `show_glyph` dispatches to `show_type3_glyph` for `PDType3Font` and to `show_font_glyph` otherwise (both now declared on `PDFStreamEngine` only, as in Java, instead of abstract on the graphics engine), and `show_type3_glyph`'s default walks the charproc through the new `process_type3_stream` (TRM replaces the CTM, concatenated with the charproc matrix, text matrices reset, no bbox clip — PDFBOX-1917). `PageDrawer#show_font_glyph` renders the real outline: `PDVectorFont#get_normalized_path` (null/empty paths are skipped, like `GlyphCache#getPathForCharacterCode`) transformed glyph→text→device space via the new `Util::Matrix#transform_point`, then filled/stroked per the text rendering mode, and `show_type3_glyph` delegates to `super` so Type 3 charprocs paint. `PDGraphicsState#text_matrix`/`#text_line_matrix` are no longer nil (Java `new Matrix()`) and the text-state accessors used by the engine (`character_spacing`, `word_spacing`, `horizontal_scaling`, `text_leading`, `text_rendering_mode`, `text_rise`, `font`, `font_size`) were added with Float64/Int32 types so both state classes answer the same messages. The unified stack also restored Java's `processStream` semantics (state saved and restored around each content stream), which exposed three real pre-existing bugs, all fixed against the Java source: `Overlay#createOverlayStream` wrote the affine matrix in the wrong order (`h 0 0 v 1 0 cm` instead of Java's flattened `1 0 0 1 h v`), `Overlay#createOverlayFormXObject` had the 90°/270° `Matrix` cases swapped (90 must be `0 -1 1 0 0 width`, 270 `0 1 -1 0 height 0`), and Java's `adjustRotation`/`createAdjustedLayoutPage` path (PDFBOX-6049) was missing entirely (now implemented with `rotatedDefaultOverlayPagesMap` caching). Fixing those exposed the last one: for PDFs with object streams, `Parser#parse_pages_from_catalog` resolved the page tree through its own `resolve_object`, bypassing the shared `object_from_pool`, so every page dictionary existed twice and page edits were dropped on save — the writer emitted the catalog-tree copy while `Overlay` mutated `document.pages` (new `resolve_page_tree_node` resolves kids through the pool). Specs: `spec/pdfbox/contentstream/glyph_dispatch_spec.cr` (3 examples; red: `undefined method 'show_type3_glyph'`), `spec/pdfbox/contentstream/type3_glyph_spec.cr` (2 examples; red: `Expected [] to eq [72]`), `spec/pdfbox/rendering/text_rendering_spec.cr` (3 examples: a `Tj` leaves the glyph outline on the raster at the text position, a text-free page stays blank, and `1 0 0 rg` fills the glyph in the non-stroking colour — the raster starts as transparent black, so "ink" requires `alpha > 0`), plus the two `graphics_operator_names_spec.cr` SCN/scn examples reworked to observe the colour *during* the stream (Java's `processStream` restores the state, so post-run inspection was only ever passing thanks to the stray stack). Full suite 2,839→2,853 examples, 0 failures; `PDFStreamEngine` showGlyph/showFontGlyph/showType3Glyph/processType3Stream, `Matrix.transformPoint`, the `Overlay` overlay-stream/form-matrix/adjust-rotation rows, the `Parser` page-tree rows and the `OverlayTest#testRotatedOverlays*`/`#testOverlayOnRotatedSourcePages` test rows are closed.
